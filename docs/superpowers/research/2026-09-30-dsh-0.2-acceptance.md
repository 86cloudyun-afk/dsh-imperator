## 研究复现与修复

| 问题 | 修复前证据 | 修复后验收 |
| --- | --- | --- |
| 主控 PTC 执行绕过 | 原生 NodePtcRuntime 的 run_code 可直接写入隔离文件，bash deny 无法阻止 | 原生 guard 在执行前拒绝 run_code，文件不存在；普通写工具也从主控面隐藏；子代理写文件成功 |
| 子代理继承主控禁令 | applyChildComposition 后子提示词含主控“你自己不动手” | spawn/fork 都传执行者 persona；子提示词没有主控禁令，包含执行与验收纪律 |
| fork 深度不一致 | depth=1 的父通过 fork 默认 maxDepth=1 时抛 SubagentDepthError | 两种 provider 都允许 depth=2，并拒绝继续到 depth=3 |
| PTC 委派/失败不可见 | PTC 派发未进入在飞统计，三次内层失败被外层成功清空 | 成功/失败/取消/未决/混合历史和去重回归通过；内层失败触发 echo，真实成功清零 |
| 驳回后无法换人 | 关闭并重开 SQLite 后，rejected 任务仍被旧 owner 锁住 | 仅可信主控能换 owner；同事务写 decision 和 handoff；两种审计写入失败均完整回滚 |
| 验证器误判宿主解析 | 已能原生 boot 的 profile 被旧 import.meta.resolve 探测报 22 项无法解析 | 使用 native RuntimeResolution 与 Cordis resolveConfig；缺必填配置、缺模块、坏行树均失败 |

## 完整 web profile 验收

以下通过原生 runProfile、Agent 工厂、ToolRuntime、taskforceStore 与 Loader 完成：

1. taskforce 在 roster 中恰好出现一次，无 broken；host store 可用。
2. 主控能看到编排/事实工具，看不到 run_code/bash/write/edit；子代理真实写入产物。
3. 创建任务→子代理认领→写证据→提交→主控验收→显式重新复核→主控换人；看板与交接记录一致。子代理自批和伪造 actor 换人被拒。
4. Agent handle 释放后，主子 Agent 均从活动表移除。
5. 通过 Loader 关闭/重新启用 host 插件，声明消失后恢复一次。
6. 制造真实 Duplicate agent preset 注册冲突，失败后占位释放；移除冲突并显式重新启用后恢复。
