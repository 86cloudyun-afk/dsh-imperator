Decision: add only `idx_fact_blocker_run_id ON fact(run_id,id,task_id) WHERE kind='blocker'`. Ceiling/member/count queries use the partial covering index. Selected rows still use idx_fact_run; an exhausted scoped continuation can scan ordinary history. Query rewriting produces the same plans and no established incremental benefit, so production SQL is unchanged. No index is forced. No ORDER BY temporary sort existed before or after; COUNT(DISTINCT) retains its valid temporary B-tree.

These are warm synthetic reads; they do not establish production migration duration, disk cost, blocker-write overhead, cold-cache latency or universal crash prevention. Index creation reads existing facts. Complete fingerprints remain O(members); returned-row counters are not SQLite visited rows.

## Final implementation and review gates

Audit migration selects original NULL parents before task changes, atomically with task/fact/handoff. Already scoped parents' NULL audit stays quarantined; originally unassigned parents with assigned audit require explicit integrity repair before adoption. Audit anomalies expose counts, never foreign contents, and refuse acceptance before evidence/waiver. Owner/generation/command/snapshot/outcome/log checks remain intact. A waiver task/run index supports per-parent audit queries.

Known SDK codes retain accurate hints and diagnostics. Stop maps only UNAUTHORIZED to ownership refusal; unknown runtime failures reconcile facts/state and report host diagnostics. Caller authority remains the exact Agent object; failed calls return no successful send/stop receipt.

Final CI, full PR review and merge evidence belongs to the PR exact-SHA ledger. This historical document does not substitute that gate.
