# 继续迭代：读快照、查询批量化与降级恢复

日期：2026-09-30。基线：PR #5，`0c9787754f95f34596bb457ee7e34ed1cff921e0`。

## 范围与设计选择

继续检查已有事实库、工作投影、guard 和宿主插件生命周期。优先修复可复现问题，不扩张成新的调度器，不修改模型权限、预设推理档位、数据库表或运行中的宿主。当前实现与测试由本会话自审，不能冒称独立审查或真实部署验收。

## 1. 同一读取操作共享一致快照

`taskOf`、`board`、`stats` 使用新的内部 `withReadTransaction` 包装；其与写事务共用回滚、失效和嵌套 savepoint 处理，顶层使用 `BEGIN DEFERRED`，不提前预约写锁。board 的内部详情读取复用已有快照，不再建立多余的嵌套读事务。该辅助函数要求同步、只读回调；它提供事务一致性，不是阻止任意 SQL 写入的权限沙箱。

原有多条自动提交 SELECT 之间，另一连接可能已提交新事实或调整归属，造成旧任务信息与新事实混合。新增测试使用两个真实 SQLite WAL 连接，在首条读取后由另一连接提交更新，验证本次读取仍返回已授权快照，下次读取看到新状态。跨归属测试的异常调整由夹具构造，不代表发现现场泄漏。

快照期间提交的更新在下次读取可见。非 WAL 部署中的读事务可能推迟其他连接的提交，所以应保持读取有界、及时结束；本轮没有自动启用 WAL。失败读取会回滚释放事务。`workingState` 原本即单条 SQL，保持不变。显式全域诊断 `statsAllRuns` 不在此次快照改造范围内。

## 2. 完整看板批量读取摘要

默认看板不再对每个任务单独调用 `#factRows`。一条窗口查询按任务选择最新五条事实，先检查任务与事实的 run 归属，再排名；窗口只携带 ID，入选后才读取正文。输出顺序、每任务上限、摘要截断、证据指针、晚到阻塞和 NULL 未归属域保持原契约。详情的 kind/confidence 计数在 SQL 分组聚合，不再把每条事实都加载到 JavaScript 中计数。

本地 Node 22.16.0、同一临时数据库、每任务八条事实的对照实验：

| 待办任务 | 原版读取查询 | 新版读取查询 | 新增事务控制语句 | 完整输出对照 |
|---|---:|---:|---:|---|
| 0 | 3 | 3 | 2 | 一致 |
| 10 | 13 | 4 | 2 | 一致 |
| 100 | 103 | 4 | 2 | 一致 |
| 1000 | 1003 | 4 | 2 | 一致 |

读取查询统计 prepare 调用，事务控制语句单列，不将 BEGIN/COMMIT 隐藏成零成本。查询数量不随任务数线性增加，不代表 SQL 扫描或排序 O(1)、总体延迟提升相同比例、模型 token 或费用降低。完整看板仍返回所有待办，体积随任务数量增长；本轮没有悄悄截断任务或改变工具 API。

## 3. 可选投影的归属与历史读取

明确传入 runId 的消费者只使用已有的 run-aware `workingState`、`stats`、`board`；不能降级到通用 `snapshot/status/state` 或对象上的全局任务字段。未指定 run 的独立调用保留旧式适配器兼容，此兼容口不由 live agent 使用。

祖先查询结果必须拥有有效的、与请求 ID 相同的会话 ID；空白、NULL、类型错误、循环或矛盾身份都停止查询 store。合法 depth-one 子代理的父会话已卸载时，仍保留既有按持久 parentSession 解析根的兼容规则。

每步只取一次会话事件快照，渲染与历史去重共享它。快照抛错或返回非数组时按缺失证据处理，不中断正常 pre-step。guard 同样容忍同步快照失败和不合法的消息块，不把对象强转为推理文本。此契约只支持同步历史接口，不承诺异步适配器或恶意 Proxy 的任意行为安全。

store 明确返回零待办时，旧 todo 不会再被投影成当前任务。状态投影仍是会话级提示，不是全树硬额度或精确代理活跃数量。

## 4. 插件激活与卸载恢复

`ctx.effect` 在调用回调之前拒绝注册时，立即释放尚未使用的 mount slot。回调已安排微任务、但 effect 注册随后失败或宿主立即卸载时，不允许微任务继续创建无人拥有的声明。已经真正开始的异步注册继续沿用等待 disposer 完成才释放所有权的规则，不抢先释放。

错误值无法转为字符串时使用安全诊断占位，不能让错误报告本身中断清理。真正卸载失败仍保留所有权，不以释放 slot 来掩盖仍可能存活的声明。不自动重试安装、重启或改宿主配置。

## 验证

新增四套回归共 35 项：context-boundaries 18、board-batching 6、read-snapshot 6、lifecycle-recovery 5，全部接入标准 `npm test`。基线 135 项增至 170 项；六套既有独立脚本同样运行。归属调整与生命周期异常均通过测试夹具主动构造。

```sh
node --test tools/tests/context-boundaries.test.mjs tools/tests/board-batching.test.mjs tools/tests/read-snapshot.test.mjs tools/tests/lifecycle-recovery.test.mjs
npm test
npm run test:integration
```

真实 DSH boot、schema 与恢复、实际模型决策质量和派发数量仍未现场验收；宿主 `UNVERIFIED` 和真身工具交叉检查 `SKIP` 不计作通过。本轮不合并、不安装、不部署、不重启宿主。阶段 B/C 全树硬额度与自动开发仍未实现。

机制依据：SQLite 官方 [隔离说明](https://www.sqlite.org/isolation.html) 与 [窗口函数说明](https://www.sqlite.org/windowfunctions.html)。代码效果以本版本测试与基准证据为准。
