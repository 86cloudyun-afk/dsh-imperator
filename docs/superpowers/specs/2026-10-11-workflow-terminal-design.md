# 工作流终态一致性设计

日期：2026-10-11（Asia/Shanghai）。基线：`3b88ba73f65379ca77cde0ff2ad2978638ff199b`，0.4.1。

用户已授权持续研究、修复和升级，完成独立审核及额外合并前审核后提交 PR、合并和实际 main 验证。本改动沿用现有工作流，不建立新编排层。

## 问题与结果

真实 SQLite 与已注册工具的最小复现证明：`task_close(failed)` 取消处于 review 的任务后，取消前的 `expected_version` 仍可被首次 `recordReview` 接受，追加审核、裁决并把阶段推进到 lead_acceptance。取消处于 plan 的任务后，`approvePlan` 同样能推进到 implement。最终验收仍被 E_TERMINAL 拒绝，故这是终态记录可被普通工作流修改的缺陷，不是已证明的非法验收。

普通工作流新变更必须在与任务读取和变更相同的写事务内拒绝现有 `TERMINAL_STATUSES`，返回既有 `E_TERMINAL`。成功旧请求的精确重放必须仍返回原结果且不写入；冲突的请求键仍拒绝。读取终态及主控显式 `returnForRework` / task_reject 重新复核保持可用。不得以增加 row_version 或伪造审核失败来代替任务终态检查。

## 范围及约束

- 修改工作流共享变更入口；保持现有角色、run、完整性、请求键、版本、证据和历史预算栅栏。
- 不改变存储 schema、依赖、版本门槛或宿主能力声明。
- 保留 `@local/dsh-taskforce`、preset `taskforce`、显示名 `任务部队`、`$DSH_HOME/taskforce/taskforce.db`。
- 保留 Node `^22.23.2 || ^24.19.0`；宿主固定为 `0.2.0-rc.2` / `0.2.1-alpha.2`。
- 验收进程 deadline 60000ms、宿主清理 12000ms；全树原生调度适配器保持关闭。
- 回归使用正常 API 构造取消、审核和恢复；基线必须先出现预期断言失败，再修改实现。

## 验收

取消后新批准和迟到审核均 E_TERMINAL，任务、flow、审核及裁决行不变化；实际重新打开数据库后仍成立。所有现有终态拒绝普通新变更。精确旧批准/审核重放无额外写入；冲突重放、跨 run、版本及角色栅栏保留。活动工作流正常推进，显式重新复核后可再次执行，执行/验收证据合同不变。通过完整离线和打包原生矩阵，完成独立任务审核、整轮审核与额外合并前审核。
