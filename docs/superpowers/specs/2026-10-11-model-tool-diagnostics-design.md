## Observation architecture and authority

The native harness installs diagnostic-only, synchronous, exception-contained public `session/created` / `session/event` observers with global/prepend delivery before creating the fresh root. Both pins enter the Session and Agent registries before announcing Session then Agent creation: initialize ownership from public `agents.get(id).session === session`, the fresh exact root ID and its already-known parent chain, rather than requiring the later `agent/created` tracking callback to have run. Unsupported or ambiguous ownership stays unavailable. It observes only that root and its actual descendants; identities and parent lineage remain internal authority, never report values. Read only the pinned SDK's audited public Session ownership/sequence APIs: durable `inheritedEventCount`, `seq` and `isOwnSeq`. An inherited seed and its synthetic closures are not new published tool actions. Never use `firstLiveSeq` or `firstLifecycleSeq` as the diagnostic ownership cut.

A cold restore retains per-session identity/parent/own-cut evidence, but setup/restoration can add legitimate unpublished seed markers or closers. The prepended creation callback validates unchanged identity/lineage/own cut and nondecreasing seq, then sets this lifecycle's publication cursor to its current public `session.seq`. Do not demand equality with the previous lifecycle's last published seq plus one. Unresolved call associations crossing an unobserved suffix become unavailable and are discarded, never presumed completed. Within the current lifecycle, require continuous publication seq; unexpected gaps/duplicate publication, duplicate concurrent session identity, changed lineage/cut or sequence rollback makes the observation unavailable instead of shifting list-length offsets. A legitimate canonical append-with-surface-replacement remains an append; repeated outcomes for one logical call are not a second success. No unavailable session or unresolved seed result can acquire a successful outcome from a different lifecycle.

Keep only bounded decoded metadata, counters and call-association state. Do not collect full histories or add new synchronous `snapshotEvents`/`ownEvents` reads; existing runtime/settlement snapshot inputs remain unchanged. At each stage start, optional `beginTaskToolDiagnosticsStage()` resets diagnostic counters and records a numeric stage cursor, preserving bounded unresolved-call association metadata. Count only new own published calls in that stage. A new-stage result can associate with an unambiguous preceding own call from before the boundary without counting that old call again. A child result referring solely to an inherited parent call is unavailable, not a successful child action.

For diagnostic lifecycle closure, also observe public `session/disposed` with the same global/prepended, synchronous exception containment. Only an already-known exact Session object can become inactive; an old same-ID disposal cannot close its replacement. This edge does not resolve an action, revive unavailable evidence, establish admission or discharge a notice. A later legitimate cold creation must still satisfy the identity, lineage, ownership and non-regression checks above. The observer does not alter the existing Agent tracker or any settlement gate.

An optional synchronous `taskToolDiagnosticsSnapshot()` returns only the fixed primitive projection below. Neither diagnostic hook calls `safeSnapshot`, reads the task store, clones arbitrary event trees, awaits work, or participates in admission/acceptance. Guard hook lookup, invocation and exact return validation together; refuse Proxy/accessor/inherited or thenable inputs without invoking their getters. A native Promise is observed only through intrinsic Promise rejection handling, never awaited or assimilated; failure returns null and preserves cancellation/original failure. Missing hooks return null. `source` is assigned by `runModelVerification` from exact native factory identity, using its existing native-versus-custom distinction, never from a hook-provided source label. Injected harness data is always `custom-harness-unverified` and cannot establish native coverage.

The hook payload has exactly the eight collector keys in the report schema after omitting `source`. A hook-provided `source` is an extra key and is rejected to null, even if its literal is otherwise valid. Only after successful projection does the wrapper add the ninth report key from factory identity; a legitimate custom payload therefore receives `custom-harness-unverified` without being permitted to self-declare provenance.

Associate native calls/results by the same session, own call seq, turn, step and call ID. Require public native message `source.kind`, `source.callId`, `toolCallId`, and canonical `sourceEventSeqs` to agree with the preceding call; reject conflicting optional event names. For PTC, use the enclosing own turn/step and native root call, then matching `rootCallId`, `parentCallId`, `subCallId` and tool name on start/result. Never correlate by subCallId alone or borrow a native wrapper result/name. Each unique logical result is counted once; duplicate/conflicting/orphan results become unavailable. Direct SDK failure is a transport error regardless of any result text.

## Exact fixed report schema

Add only stage fields `taskToolDiagnostics` and `timeoutTaskToolDiagnostics`, each null when unavailable; the timeout field is otherwise captured and copied before cancel, independent of subsequent final observations. Do not change either existing progress object. A non-null diagnostic has exactly these keys:

```text
source: native-own-published-events | custom-harness-unverified
observedEvents: integer
unattributedResults: integer
byTool: { every TOOL: { calls, nativeResults, ptcResults,
                      envelopeOk, envelopeError, transportError, unavailableResults } }
byRole: { root: integer, worker: integer, unknown: integer }  // observed calls only
errorCounts: { every CODE: integer }
details: [{ toolName: TOOL | null, role: root | worker | unknown,
            presentation: native | ptc,
            outcome: envelope-ok | envelope-error | transport-error | unavailable,
            errorCode: CODE | null, eventIndex: integer | null }]
truncated: boolean
saturated: boolean
```

TOOL is exactly `task_open`, `task_claim`, `task_fact`, `task_submit`, `task_accept`, `task_reject`, `task_close`, `task_board`, `task_child_send`, `task_child_stop`, `task_verify`, `task_checkpoint`, `task_workflow_create`, `task_workflow_submit`, `task_workflow_state`. Root/worker calls are attributed only by the actual root and valid descendant lineage; unsupported ownership is unknown. A raw unexpected name never becomes an object key or string value. A result unable to establish one of these logical tools contributes only `unattributedResults`, without inventing a successful per-tool outcome.

CODE is exactly `E_NO_AGENT`, `E_NO_SESSION`, `E_NO_AGENTS_SERVICE`, `E_TERMINAL`, `E_STATUS`, `E_EVIDENCE_MISSING`, `E_BLOCKERS`, `E_TASK_CONFLICT`, `E_CROSS_RUN`, `E_NOT_FOUND`, `E_CHILD_SERVICE`, `E_CHILD_INPUT`, `E_CHILD_NO_AGENT`, `E_CHILD_NOT_OWN`, `E_CHILD_MISSING`, `E_CHILD_SETTLED`, `E_CHILD_NO_ID`, `E_CONTROL_JOURNAL_UNAVAILABLE`, `E_CONTROL_OUTCOME_UNKNOWN`, `UNAUTHORIZED`, `NOT_RESUMABLE`, `ABORTED`, `unknown`. These are observed code literals, not certainty judgments about an external action. `envelopeOk` / `envelopeError` mean only a decoded own Boolean `ok`; neither means actual completion, acceptance, effect certainty or native activation. In particular, `E_CONTROL_OUTCOME_UNKNOWN` / `E_CONTROL_JOURNAL_UNAVAILABLE` never assert that an external action definitely failed. `errorCounts` counts the recognized envelope code on `ok:false`; absent, invalid or unlisted error codes use `unknown`. SDK transport errors contribute `transportError` and leave application envelope counts untouched; their error codes remain governed by the existing runtime diagnostics.

Decode only an unambiguous associated TaskForce result with exactly one public text block and a JSON object with an own Boolean `ok`. Additional JSON envelope fields are neither copied nor reported. Malformed/multiple/non-text/oversize content or unsupported shape of a uniquely associated result is unavailable. `nativeResults` / `ptcResults` count associated unique logical results, partitioned by envelopeOk/envelopeError/transportError/unavailableResults; a native `run_code` wrapper is not an additional TaskForce result. A duplicate or conflicting result for an already resolved call contributes only `unattributedResults` and an optional bounded unavailable detail, never another native/PTC or per-tool unavailable result. Conflicting coordinates that prevent unique association are likewise unattributed. Thus each tool satisfies nativeResults+ptcResults = envelopeOk+envelopeError+transportError+unavailableResults until explicit saturation. Details contain results only and no arguments, body, exception text, identities, paths or request keys.

## Fixed resource limits

Maximum 16 scoped sessions and 4096 observed own published events per stage, 4096 retained call associations across the fixture, one 65536 UTF-8 byte result envelope and 2097152 decoded UTF-8 bytes per stage. Check character length before computing/decoding byte length; bounds are applied before parsing, copying or retaining content. Retained coordinate strings have at most 256 UTF-8 bytes and are internal only. Preserve no full raw result/argument text in this collector. Details have at most 20 entries; beyond that only counters advance and `truncated` is true. Budget exhaustion makes further results unavailable and sets `truncated`, never completes an action or relaxes a gate. Every counter is a safe integer in 0..65535; clamp and set `saturated` on overflow. Snapshot work is bounded copying of the fixed maps and at most 20 primitive details, with no history scan. Immutable snapshot validation rejects extra keys, inherited/accessor/Proxy properties, invalid literals and counters outside these bounds. Faults in diagnostic acquisition/publication must be contained and can only degrade its availability, not native behavior.
