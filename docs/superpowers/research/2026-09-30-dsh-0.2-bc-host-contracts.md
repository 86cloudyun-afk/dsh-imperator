## 3. 明确的变化及其影响

### 3.1 宿主版本与失败 step 的工具结果恢复

本轮明确的相关 upstream 行为变化为 `ToolCallRecovery` 及 loop 的 live failed-step catch 路径。所比较的 create/delegation/continuation/drain/query/persistence/ToolGuard/jobs/shell 契约文件没有相关 API 变化；不能把“0.2 可用”写成“0.2 新增”。39 个文件中的 5 个差异均在 agent-loop/session 的恢复实现或声明，未对全包作兼容断言。

- `TOOL_NOT_STARTED`：日志未记录对应 `tool/call` 开始；不是全系统“无副作用”的证明。
- `TOOL_OUTCOME_UNKNOWN`：日志记录了调用，但缺可配对结果；不是失败、成功或停止证明。
- recovery 只配对所属 turn/step 的 append 结果；展示 replacement 不清除另一次调用的 pending 身份。tool 事件须绑定实际 session/turn/step、日志 seq 及 surfaceOp/原始事件引用（如实际提供的 sourceEventSeqs）；replacement 的新 seq 归回原始逻辑调用，不产生新执行/effect。缺可靠原始关联时标记能力不明/不可采信，不假定所有事件都有来源引用字段。
- 调度器只能按自己的可信 dispatch/attempt、持久结果和 quiescence 证据结算。单个取消/失败观察事件不能释放；**持久失败/取消结果 + 完整回收证明**齐备时可以结算 failed/cancelled 并释放。只有证实从未运行的执行才用 never_started。

### 3.2 PR #6 的 TaskForce 适配变化

PR #6 已把现有产品适配到 0.2：root 禁止 PTC 直接执行、原生展示、执行 child persona、spawn/fork depth 2、PTC/原生事件身份按 turn/step 配对，以及原生 resolver/验证器清理处理。B/C 要沿用这些实际改动，不另建一套较弱事件身份或把 root 禁令继承给所有 child。

该验收通过了现有 preset/事实库的原生路径。它没有模型请求，未交付持久队列、自动化 runner、PR provider 或 B/C 生产回收。Loader 重新启用不等于宿主崩溃恢复；深度 helper 通过不等于长时两层委派通过。

## 5. 实现后、启用前的集成门槛

1. B 离线核心完成迁移/回滚、事务竞争、幂等、FIFO 写屏障、跨 run 资源互斥、6/2 全树预算和过期 generation 拒绝，证据与 native 结果分开。
2. 在精确宿主复验创建到回收的故障窗口、外部目标输入、实际两层模型委派、长时任务、后台 shell/jobs、parent/插件退出和崩溃重启；保存版本/配置/代码 hash 与结果。不请求模型的 PR #6 验收不能替代这些门槛。
3. C 按完整 SHA/plan/revision/policy 验证测试、独立审查与 accept；所有实现后代排除于审查者且已静止。持久成功回执先到也不提前释放或晋级。
4. C 用授权测试仓库验证 runner/产物/PR 的 durable lookup 和崩溃恢复；未知占用保持，外部动作不宣称 exactly-once，不自动 merge。

本轮完成的是规格对齐、发布包取证和验收覆盖审计。B/C 产品、上述 spike、长期模型执行以及真实部署均未在本轮实现或验收。
