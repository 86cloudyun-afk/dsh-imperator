# Imperator 0.3.0：可信交付与有界编排

用户目标：依据 2026-10-08 实测推进下一版，完整实施、上传 PR，另起独立审核，问题全部处理后合并。此次授权包括设计取舍、实施、推送、创建 PR 与合并。版本目标为 `0.3.0`，不是 npm 发布。

## 范围与不变契约

此次交付连接同一任务生命周期的身份、编码验收、看板、历史投影、运行预算基础与模型回归。包名 `@local/dsh-taskforce`、preset `taskforce`、显示名 `任务部队`、数据库 `$DSH_HOME/taskforce/taskforce.db` 不变；零外部运行依赖。Node 支持 `^22.23.2 || ^24.19.0`，精确宿主验收基于 `@deepseek-ai/dsh@0.2.0-rc.2`。主会话只读调查与验收，子会话执行；不能通过新验证工具绕过宿主的 approval、sandbox 或 guards。STALL 仅观察、`stepDownRequests: 0` 不变。

## 1. 真实执行者

`task.owner` 保留显示标签，新增 nullable `owner_session`；历史数据不猜测标签对应的会话。工具层在子会话认领时将真实调用者会话作为独立可信参数传入；模型的 `child_id` 仅影响显示标签，不能选择另一会话。主会话指定实际直属或后代会话 ID 时，必须由宿主解析并核对同 run 血缘后绑定；仅标签的预指派属于未绑定状态，需要执行者自己认领后绑定。无法核验的目标不得被当成可信会话。

绑定任务的重复认领、提交、取消由真实 owner 或主会话执行；其他子会话不得凭相同显示标签取得权限。事实允许同 run 协作追加与报告 blocker，但模型不能伪造署名；新增 `fact.actor_session` 保存真实调用者，旧 `created_by` 保持兼容显示。主会话重新指派只能在 rejected 状态，绑定更新和 handoff/audit 同事务。旧的未绑定任务保留历史提交路径并返回兼容警告；旧取消规则保留，不擅自迁移身份。旧执行者在已重新绑定后失去提交与取消权。所有状态优先级、跨 run 隔离、终态冻结和晚到 blocker 行为保留。

## 2. 编码任务严格回执

`task_open` 新增 `evidence_policy: 'legacy' | 'execution'`，默认 `legacy` 保留调查任务与现有客户端。`execution` 要求非空 `verification_files` 相对路径清单与固定 `verification_command`；只能由主会话或宿主可信端口创建，可信会话 cwd 固定为此任务工作区。路径不得逃逸、指向外部 symlink 或缺失文件。该清单是此次验收的明确代码快照范围，不宣称覆盖清单外文件或恶意进程的物理隔离。

新增仅子会话可调用的 `task_verify(task_id, command, timeout_ms?)`；command 必须逐字匹配任务创建时固定的 verification_command，不能用另一条 exit 0 命令替代约定验收。内部调用真实宿主 `tools.execute` 的 `bash`，传递真实 agent 与取消 signal，保留宿主执行政策。缺少宿主执行能力返回 `E_VERIFICATION_CAPABILITY`，不能降级为解析模型文本。默认超时 60000 ms，合法范围 1–120000 ms。回执在工具返回前持久写入同数据库，关联 run、task、当前 `evidence_generation`、真实执行者、命令、开始结束时间、清单文件 SHA256、stdout/stderr 内容与摘要、实际退出码/信号、timeout/abort、是否输出完整。输出大于 2 MiB 或被截断、后台 promotion、拒绝/基础设施失败、代码执行期间变化均不构成成功。日志存入宿主事实库目录的 receipts 子目录，模型不能指定回执字段或日志路径。这是工具接口层的宿主观测证据，数据库和回执目录不构成抵抗同 UID unrestricted shell 恶意篡改的物理安全边界。

严格验收只采信本代、本 owner、同 run 的最新回执：真实 foreground 退出码 0、无 signal/timeout/abort、完整日志及其 SHA256 可重查、当前清单快照与回执一致。不存在的、被改过的或缺失的日志、过期代码、非零运行不能被 artifact 陈述掩盖。reject 增加 `evidence_generation`，旧回执不能复用；同代较新的失败覆盖早先成功。显式主会话 `waiver_reason` 仍可走人工豁免，单独审计并明确不是验证通过。事实可作为解释与产物指针，但不能伪造 host receipt。

## 3. 有界看板

保留 `store.board` 作为兼容宿主 API；模型默认 `task_board` 改用 `store.boardPage`。默认每页 25，最大 100，非法或超界页参数拒绝。按 ID 降序、`id < cursor` 做 keyset 分页；返回完整全域总数与独立游标，不将当前页条数当成任务总数。`view` 支持 `tasks`、`summary`、`facts`、`handoffs`、`late_blockers`；facts/handoffs 必须指定 task_id。task_id 无 view 保持详情入口，并暴露继续读取全部历史的游标。

默认待办页附每任务最新一条简短事实（标题/标签/摘要截断展示，原文通过详情/事实页可取）。所有分页均按 run 与父任务校验。晚到 blocker 单独分页并返回全量总数、`has_more` 与 `next_cursor`，默认页即使为空也不能隐去报警入口。默认 tasks/summary 输出必须 <=65536 UTF-8 bytes：有明确 `truncated`/游标元信息的有界展示，不静默裁掉条目或警报。详情事实不截断内容，页数有界；通过 facts/handoffs/late_blockers 页可取全。记录 1000/5000 任务量级的字节数和查询性能，不以墙钟阈值写脆弱测试。

## 4. 增量历史投影

把工具坐标扫描与 guard/flow 的累加状态拆为可恢复 reducer，现有纯全量折叠函数继续作为重放与兼容入口。运行时为每 agent 保留缓存，只对可信不可变快照的追加尾部更新；按对象身份检查整个旧前缀，替换、重排、缩短、选项变化或非深冻结输入必须全量重放。不能凭最后 seq 或最后 callId 假定前缀未变。DSH 0.2.0-rc.2 新建事件是 deepFreeze 的；非 immutable 冷读/测试输入保守回退。

保持 native/PTC 的 turn/step/call 身份、乱序结果、重复结果、ECHO 通知确认、同发送者不同通知、pending 调用及 todo/context 去重语义。snapshot 不能把未关闭的当前 step 多次计入 STALL。默认不降低推理档位。性能验收包括深冻结的 40000 事件追加一次时累计处理数量只增加新增事件，且与全量重放结果一致；不把前缀身份检查称为 O(1)。

## 5. 阶段 B 的持久准入基础

此次交付是阶段 B 的第一批：同 SQLite 的 governor 核心、事务准入、幂等操作、generation fence、共享资源互斥与 unknown 保留。不是完整队列、生产派发或后台进程回收。原生适配器在目前 H01–H06 未解除时明确返回 `E_SCHEDULER_CAPABILITY`，不得仅凭配置布尔值启用生产 guarantee。当前 continuable 提示词预算仍须如实标注为软纪律。

每 run 全树最大同时活动总数 6，其中含写最大 2；累计新建 3，每任务 retry 最大 2；复用与新建分开计数，嵌套共用 root run 计数。资源键由可信宿主提供；不同 run 的同资源写互斥，读共享，unknown/reserved/running 均占用。准入不足返回稳定错误，不静默排队；操作键相同且内容相同幂等，内容不同拒绝。reserve/bind/markUnknown/settle 都带 generation；旧代拒绝。只有可信 `never_started` 或终态加 quiescence 证明才释放资源，cancel 请求与 idle 不能释放。重启后所有未知占用保留，不盲目重放。扩展预算需可信 lead 及非空理由且审计，不能通过新建虚构里程碑重置。

该核心 API 属宿主可信端口，不是模型可伪造的工具参数；数据库不是抵抗本机恶意写入的安全边界。具体 OS quiescence 由未来经验证的执行适配器提供，此版本不制造该证明。

## 6. 简短流程与回归

低风险小任务默认：只读问题主会话直接处理；需写入/执行时一条可验收任务、一名执行者，按里程碑落关键依据，提交后一次主控验收；已有执行者优先续作。不要求每一步都落事实、重复决策或重复复述。高风险和证据矛盾仍使用独立审查。压缩重复 persona 与工具描述，保留所有执行/隔离/证据边界；通过真实 native schemas 记录字节变化，不以字符测试替代行为验收。

新增 opt-in `tools/verify-model.mjs`，不加入默认 npm test 的付费调用。固定只读、金额精度修复、同执行者 NaN/Infinity 续作、严格回执任务，独立测试固定题目，不能只运行模型自行写的测试。参数包括精确 host anchor、provider/model、request cap、阶段 timeout、输出目录；必须显式 `--model-calls` 才能联网调用。报告绑定包版本、完整 git commit（如果可取）、产品源码树 SHA256、npm 包 SHA256（若提供）、宿主/Node 版本、请求/输入输出缓存 tokens、时长、新建/复用/返工、事实/验收结果与独立测试。失败、超时、缺 usage 或不完整闭环不能标记通过；不保存 reasoning 或 credentials。

## 交付验证与审核

新增测试登记于 runner 及镜像；契约 guard 修改做变异自证并恢复。各任务先行为测试失败、再实现、定向验证、提交，独立 reviewer 同时检查 spec/quality。最终 npm pack 在 Node 22.23.2 与 24.19.0 跑完整原生矩阵，再跑固定模型集；离线/native/model 分开报告。将 PR 创建后再派全分支独立 reviewer，所有可操作缺陷修复并复验，核对 CI 和精确 head 后合并。alpha 仅作为后续隔离兼容目标，此版继续用实际验收的 rc.2，不提前承诺 alpha 支持。
