## 1. 目标与范围

用户已明确两方面都要：一是稳定性、防误验收和故障恢复；二是并发调度和自动开发能力。本设计采用分阶段增量改造，先保证任务状态可信，再让更多代理在这套状态之上协作。

沿用现有的 DSH host 服务、agent preset、SQLite 事实库及原生子代理生命周期。主代理负责拆解、分派、核对和汇报，执行工作由子代理承担。现有默认 `maxDepth: 2` 保留；新增调度规则覆盖整棵任务树，避免子代理再派活绕过总额度。

成功标准：

- 任务状态、验收依据和审计记录一致，任何一步失败都不留下半完成的裁决。
- 插件卸载、重新启用、注册失败后的恢复不产生僵死占位或重复注册。
- 并发额度和资源冲突由持久状态与执行入口共同控制，排队原因可解释。
- 自动开发按计划、实现、测试、独立审查、验收推进，证据与实际代码版本绑定。
- 测试覆盖失败、竞争、重启和重复通知；真实 DSH 验收与隔离模拟分别报告。

## 3. 方案比较与选择

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| 分阶段扩展现有服务 | 保留已验证行为，逐步加入事务、调度和开发流程 | 需要迁移与宿主集成测试 | 推荐 |
| 只加强 persona 和文档 | 改动小 | 无法保证原子性、资源互斥和验收门槛 | 不足以满足目标 |
| 重写为完整独立代理平台 | 自由度高 | 替换宿主生命周期，迁移与运维成本大 | 本轮不采用 |

交付分为 A、B、C 三个独立阶段，每阶段有自己的验收和 PR。A 先落地；B、C 的总体目标纳入本轮，但在实现各自子系统前补齐其详细接口规格与宿主契约验证。

## 4. 阶段 A：可靠性修复——首个实施范围

### 4.1 事务与竞争控制

在事实库内部提供同步事务边界。事务内只执行数据库操作，不持锁等待网络、模型或文件处理。

- 验收、打回、提交附注、取消附注、认领、历史归属迁移以及事实插入与任务时间更新，都按一个业务动作提交或回滚。
- 最外层写事务使用 `BEGIN IMMEDIATE`；需要组合内部动作时使用 savepoint 或明确的内部无事务方法，避免重复 BEGIN。
- 状态检查和条件更新处于同一事务，保留 run 隔离与终态冻结。并发认领只允许一个成功，失败返回稳定的冲突码。
- 开库、列迁移和视图更新作为一个迁移动作执行；失败关闭临时句柄，之后可以重新尝试。
- 锁竞争返回可辨识的错误，不进行无限重试。等待预算有明确配置和上限；WAL 作为显式配置项，启用后核对实际 journal 模式。
- 用本地临时数据库进行故障注入和多连接/多进程竞争测试，验证回滚、迁移幂等及锁释放。

### 4.2 验收与阻塞语义

基础模式收紧两项硬规则：REFUTED 记录不计入正常验收依据；解阻塞必须使用同任务的 decision，且不能是 REFUTED。保留显式 `waiver_reason` 路径并准确记录已有依据数量。

- 新写入不合法解决记录时直接拒绝；已有不合法解决记录也不能在查询中继续消除 blocker。
- 看板、统计和验收统一复用有效解决记录的判据，避免不同页面显示不同的阻塞状态。
- 已落盘的历史 accepted 状态不自动推翻；如发现历史验收依据不足，通过诊断展示并走现有显式复核流程。
- 基础任务允许非 REFUTED 的调查记录，并对缺少证据指针发出明确提示。阶段 C 的开发流程采用更严格的版本、测试和审查证据要求。
- 数据层验证结构与状态；文件内容是否支持结论，仍由核对者验证。仅有路径不宣称已完成内容核验。

### 4.3 插件生命周期

将当前永久 Set 占位改成带所有权和生命周期的注册记录。重复挂载期间仍只存在一个有效声明。

- 卸载释放属于本实例的占位；注册失败释放占位，允许后续显式重新激活。
- 异步注册返回之前发生卸载时，迟到的 disposer 必须执行，不能重新挂回预设。
- 旧实例的迟到回调不能清除新实例的注册记录。
- 撤销失败必须保留诊断状态，不直接谎报已卸载；避免留下未追踪的有效注册。

### 4.4 测试入口与文档

为现有七套脚本建立统一入口，区分可独立运行的测试与需要 DSH 的集成验证。新增 GitHub Actions 执行独立测试；宿主依赖缺失时明确报告集成未验证，不显示“全部集成通过”。

主要涉及 `lib/store/index.js`、`lib/index.js`、必要的工具错误映射、`package.json`、验证脚本、工作流配置及 README/STORE 文档。原有案例继续覆盖；涉及新验收语义的夹具明确更新，不能通过删除断言掩盖回归。

阶段 A 验收：R1 注入失败后状态仍为 submitted 且可重试；R2 非法解决记录不能消除 blocker；R3 重启用能恢复且无重复挂载；R4 仅 REFUTED 依据被拒。原有正常提交、验收、复核、跨 run 拒绝及子代理控制行为仍成立。

## 5. 阶段 B：持久化并发调度

在 host 平面增加调度服务，使用阶段 A 的事务能力维护依赖、排队、执行尝试、额度和资源持有者。agent 工具只提交请求、读取状态与执行已获准的任务。

### 5.1 调度策略

- 默认每个 run 最多 6 个活动任务，其中写任务最多 2 个；所有后代共享额度。宿主可配置更低的全局总额度。
- 任务声明 read/write 类型、依赖和资源。只读可共享同一资源；同资源写入与读写冲突串行。未知执行能力按写任务处理。
- 路径归一化在可信宿主侧进行；仓库、工作区和分支更新各有资源标识。相同物理工作区的冲突跨 run 生效，但不向模型泄露其他 run 的任务细节。
- 依赖必须在同一 run，拒绝不存在的引用与环；依赖 accepted 才可派发。失败或取消的依赖令下游保持阻塞并显示原因。
- 初版使用有界队列和 FIFO；不引入复杂优先级抢占。队列容量和并发上限由配置给定。

### 5.2 可靠派发与恢复

每次执行分配唯一 attempt 与代际标识，领取和资源占用原子提交。派发意图持久化，成功的 childId、失败原因及结算均可对账。

宿主创建子代理与 SQLite 不是同一个事务。若创建结果不确定，进入 reconciliation 状态，查宿主持久目录确认；不盲目重派，不承诺外部副作用的 exactly-once。

心跳过期只表示失联，不能证明旧执行者已停止。未知活动态保留资源占用并进入恢复处理；确认停止后才能重新分配。迟到提交必须校验 attempt 代际，旧执行者不能覆盖新结论。

代码写任务使用独立工作区或 git worktree；最终分支更新串行。数据库代际校验不被描述为文件系统隔离，旧进程对文件的写入风险通过工作区隔离与版本化交付处理。

### 5.3 宿主适配门槛

仓库已给出 sendMessage、interrupt、listChildren 的实际契约，但没有足够材料证明创建子代理入口与派发结果事件的完整契约。实施调度接入前，必须取得目标 DSH 版本的这些接口或源码并验证：

1. 创建子代理请求、返回 childId 与失败语义。
2. 派发前准入和派发后结果的可挂接位置。
3. 重启后的持久目录、活动态与结算事件标识。
4. 重复事件、取消、父会话退出及插件卸载的处理。

适配不可用时返回明确的能力缺失，不能退化成“提示词限流”并宣称硬调度已生效。调度保证只覆盖受管的任务与入口，不扩大为整个宿主或所有 shell 的安全边界。

阶段 B 验收：竞争领取不超额；父子树共用额度；同资源互斥；依赖环被拒；重复结算不重复释放；失联不会提前释放写锁；重启不盲目重复派活。模拟测试和真实宿主测试均需通过才能宣称集成完成。

## 6. 阶段 C：自动开发与独立审查

在同一事实库上增加开发工作流记录，阶段为计划、实现、测试、独立审查、主代理验收、交付。阶段状态单独建模，不把阶段 B 的运行状态和原有任务状态混成一个字段。

- 计划包含目标、修改范围、验收命令和边界；执行者按自包含任务说明领取工作。
- 实现交付绑定仓库、分支或工作区以及精确 commit SHA。未提交工作不能直接进入最终交付验收。
- 测试证据记录实际命令、退出码、日志位置及所测 SHA。无法运行必须记为未验证，不能用口头“通过”代替。
- 独立审查由不同于实现者的会话执行，记录需求符合性与代码质量结论，并绑定被审查 SHA。
- 测试或审查失败进入返工，默认最多 2 轮自动返工；达到上限或发生不确定副作用时转阻塞，由主代理汇报与调整。
- 任何代码版本变化都会使旧测试与审查失去对新版本的验收资格。主代理只有在必需证据有效、没有未解阻塞时才能验收。
- 开发任务的严格证据模式要求已确认结论和可定位产物；反证型研究仍可通过单独的已确认研究结论交付。
- 交付先形成可审查的分支/PR。自动合并作为显式启用的工作流策略，必须核对目标 SHA、权限和仓库检查；本设计审阅不视为对任意未来 PR 的合并授权。

新增可见工具集中于工作流创建、阶段提交、状态读取及调度动作；不为每个内部状态扩充一个工具。工具名和字段在该阶段的详细规格中一次性确定，并做宿主兼容测试。

阶段 C 验收：同一执行者不能自审；失败测试不能进入验收；SHA 变动使旧证据失效；返工次数受限；完整闭环可从重启断点恢复；最终交付能追溯到命令、日志、审查者和代码版本。

## 7. 兼容、交付与验证

阶段 A 首先交付，不依赖新调度服务；B 依赖 A，C 依赖 A 和 B。新增持久结构采用版本化、可重复执行的迁移，保留旧行，不自动重写历史结论。上线前在数据库副本验证迁移，并准备应用与数据库成对恢复；不能在未验证兼容性时声称旧代码可安全打开升级后的库。

独立测试在当前环境执行，真实 boot、preset 挂载、运行中卸载重启用、父子消息流与恢复在目标 DSH 环境验收。真实环境缺失时，交付注明对应验收未完成。

每阶段按“复现或失败测试 → 最小实现 → 回归测试 → 审查 → PR”推进。出现新的宿主契约限制先更新设计，不通过猜接口或放宽判据绕过。
